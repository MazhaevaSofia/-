# Формат пользовательских сценариев

Чтобы добавить свой уровень-расследование в тренажёр без изменения кода
Python, положите `.json`-файл в папку `scenarios/` в корне проекта. Он
автоматически появится в игре в разделе **«📄 Свои сценарии»** на экране
выбора уровня.

Готовый пример: [scenarios/example_ransomware.json](scenarios/example_ransomware.json).

## Структура файла

```json
{
  "id": "уникальный_идентификатор",
  "title": "Название, которое увидит игрок",
  "technique": "T1486 - Data Encrypted for Impact",
  "description_lines": ["строка 1", "строка 2 (пустая строка тоже допустима)"],
  "analysis_steps": [
    {
      "id": "detection",
      "button_label": "1. Обнаружение атаки",
      "title": "1. Обнаружение атаки",
      "content": ["строка описания 1", "", "строка 2"]
    }
  ],
  "unlock_action": {
    "button_label": "Заблокировать IP атакующего",
    "prompt_title": "Командная строка — блокировка IP",
    "instruction": "Введите команду для блокировки IP:",
    "command_hint": "netsh advfirewall firewall add rule ...",
    "success_command": "netsh advfirewall firewall add rule ...",
    "success_message": "IP атакующего заблокирован"
  },
  "quiz": {
    "questions": [
      {
        "question": "Текст вопроса",
        "options": ["вариант A", "вариант B", "вариант C"],
        "correct": 0,
        "explanation": "Почему именно этот ответ верный — показывается игроку после ответа."
      }
    ]
  }
}
```

## Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный идентификатор сценария (латиницей, без пробелов). |
| `title` | да | Название уровня, показывается игроку. |
| `technique` | да | Строка вида `"T1055 - Process Injection"` — техника MITRE ATT&CK, идёт в заголовок экрана расследования. |
| `description_lines` | да | Список строк вступительного описания на главном экране. Пустая строка `""` — пустая строка в интерфейсе. |
| `analysis_steps` | да, ≥1 элемент | Этапы анализа. Каждый — кнопка на главном экране, при клике открывающая текст. |
| `analysis_steps[].id` | да | Уникальный внутри сценария идентификатор этапа. |
| `analysis_steps[].button_label` | да | Текст кнопки на главном экране. |
| `analysis_steps[].title` | да | Заголовок на экране этапа. |
| `analysis_steps[].content` | да | Список строк текста этапа (с прокруткой, если не помещается). Строки, начинающиеся с `-`, подсвечиваются другим цветом. |
| `unlock_action` | да | Финальное защитное действие — открывает окно командной строки. |
| `unlock_action.button_label` | да | Текст кнопки на главном экране, открывающей командную строку. |
| `unlock_action.prompt_title` | да | Заголовок окна командной строки. |
| `unlock_action.instruction` | да | Подсказка над полем ввода. |
| `unlock_action.command_hint` | да | Пример команды, показываемый игроку. |
| `unlock_action.success_command` | да | Команда, при вводе которой (без учёта регистра) действие засчитывается. Слово `skip` всегда срабатывает — удобно для тестирования. |
| `unlock_action.success_message` | да | Текст, добавляемый в лог выполненных действий при успехе. |
| `quiz.questions` | да, ≥1 элемент | Финальный тест — тот же формат, что в `game/data/quiz_data.py`. |
| `quiz.questions[].question` | да | Текст вопроса. |
| `quiz.questions[].options` | да | Список вариантов ответа (обычно 3). |
| `quiz.questions[].correct` | да | Индекс правильного варианта в `options` (с нуля). |
| `quiz.questions[].explanation` | нет, но рекомендуется | Объяснение, показываемое после ответа — без него игрок увидит только «ВЕРНО/НЕВЕРНО». |

## Проверка сценария

Игра проверяет структуру файла при запуске и пропускает (с сообщением в
консоли) файлы, которые не проходят валидацию — сломанный сценарий не
уронит игру, но и не появится в списке. Чтобы проверить файл вручную:

```bash
python3 -c "from game.core.scenario_loader import load_scenario; load_scenario('scenarios/мой_сценарий.json')"
```

Если ошибок нет, команда завершится без вывода.
